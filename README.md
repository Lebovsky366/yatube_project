# Yatube – это социальная сеть для публикации дневников. Учебный проект на Django. Пользователи могут регистрироваться, создавать посты, объединять их в группы, искать записи, управлять профилем, восстанавливать пароль. Админка позволяет управлять всем контентом. Вёрстка сделана с помощью Bootstrap 5 с кастомными стилями.

# ЗАПУСК ПРОЕКТА С НУЛЯ (на любом компьютере)

### Первый шаг – клонирование репозитория. Открываю терминал, перехожу в пустую папку и выполняю git clone https://github.com/Lebovsky366/yatube_project.git. Затем перехожу в папку yatube_project.

### Второй шаг – создание и активация виртуального окружения. Создаю venv командой python -m venv venv. Активирую через source venv/Scripts/activate (для Windows Git Bash).

### Третий шаг – установка зависимостей. Устанавливаю всё, что перечислено в requirements.txt: pip install -r requirements.txt.

### Четвёртый шаг – миграции и запуск. Перехожу в папку yatube (там лежит manage.py) и выполняю python manage.py migrate. Затем запускаю сервер: python manage.py runserver. Сервер поднимается на http://127.0.0.1:8000.

Если я ещё не создал суперпользователя, делаю это отдельно: python manage.py createsuperuser. Логин и пароль я запоминаю – обычно admin и admin123. Суперпользователь нужен для входа в админку и для проверки функций, доступных только авторизованным.

Для быстрого запуска на экзамене я могу скопировать одну большую команду, которая делает всё по порядку – клонирование, переход, создание venv, активация, установка зависимостей, миграции и запуск сервера. Это экономит время.

# СТРУКТУРА САЙТА И ОСНОВНЫЕ СТРАНИЦЫ

Главная страница (/) – показывает последние 10 постов, наверху есть строка поиска, справа статистика (количество постов, пользователей, групп) и список всех групп.

Страница группы (/group/<slug>/) – открывается по клику на название группы под постом. Показывает посты, которые относятся только к этой группе.

Создание поста (/create/) – доступно только авторизованным пользователям. Если не залогинен, Django перенаправляет на страницу входа – это работа декоратора @login_required.

Вход (/auth/login/) – форма с полями «Имя пользователя» и «Пароль».

Выход (/auth/logout/) – завершает сессию и показывает страницу с сообщением о выходе.

Регистрация (/auth/signup/) – форма с полями: имя, фамилия, username, email, пароль и подтверждение.

Профиль пользователя (/auth/profile/) – показывает имя, email, дату регистрации. Доступен только авторизованным.

Смена пароля (/auth/password_change/) – форма со старым паролем, новым паролем и подтверждением.

Восстановление пароля (/auth/password_reset/) – вводится email, после чего письмо со ссылкой для сброса сохраняется в папку sent_emails (настройка filebased.EmailBackend).

Админка (/admin/) – доступна только суперпользователю. Там можно управлять постами, группами и пользователями.

JSON-эндпоинт (/api/posts/) – возвращает все посты в формате JSON с полями id, text, pub_date, author, group. Это пример сериализации данных.

### Шаг 8. Поиск по постам. В строке поиска в шапке ввожу слово, которое есть в каком-то посте. Страница обновляется и показывает только те посты, где это слово встречается. Это работает через ORM-фильтр text__icontains.

ВОПРОСЫ, КОТОРЫЕ МОГУТ ЗАДАТЬ, И МОИ ОТВЕТЫ

Зачем нужен декоратор @login_required? – Он ограничивает доступ к странице создания поста. Если пользователь не авторизован, его перенаправляет на страницу входа. Это защита маршрута на уровне view.

Как работает восстановление пароля? – Пользователь вводит email. Django генерирует одноразовую ссылку и отправляет письмо. В моём проекте письма сохраняются в папку sent_emails. По ссылке пользователь попадает на форму, где задаёт новый пароль.

Как устроен поиск? – В index я получаю параметр q из GET-запроса, затем применяю filter(text__icontains=q) к QuerySet. Это делает поиск без учёта регистра.

Какая база данных используется? – SQLite. Она не требует отдельной установки, файл db.sqlite3 лежит в папке проекта. Для демонстрации я добавил его в репозиторий, поэтому на экзамене данные уже будут.

Как я тестирую проект? – Я написал два класса тестов: один проверяет создание поста, другой – доступность главной страницы и наличие контента. Запускаю их командой python manage.py test posts.

Что такое сериализация и зачем она нужна? – Это преобразование объектов модели в JSON для передачи по API. В моём проекте это реализовано через метод to_dict в модели Post и view-функцию api_posts, которая возвращает JsonResponse.
